# @viet-asr/web — WebAssembly / browser binding

Offline Vietnamese Speech AI SDK for the browser. Runs **fully on-device** — no server, no upload.

## Architecture

The browser binding splits the pipeline across two runtimes:

```
                  ┌─────────────────────────────────────────┐
  audio (mic /    │  JS  (src/index.js)                     │
  file / stream)  │   - orchestration                       │
        │         │   - carries att_cache / cnn_cache       │
        ▼         └───────────┬─────────────────┬───────────┘
                              │                 │
              ┌───────────────▼──────┐   ┌──────▼────────────────┐
              │  WebAssembly         │   │  onnxruntime-web      │
              │  (vietasr-core.wasm) │   │  (model.onnx)       │
              │   - fbank front-end  │   │   - streaming         │
              │   - CTC beam search  │   │     Conformer encoder │
              │   - BPE detokenize   │   │                       │
              │   - ITN normalize    │   │                       │
              │   - resampler        │   │                       │
              └──────────────────────┘   └───────────────────────┘
              (compiled from the shared    (the same model.onnx
               C++ core — identical to      shipped to every other
               every other binding)        vietasr binding)
```

The model is **not bundled** in the npm package — that would bloat it past
60 MB. `model.onnx` lives in the repo as <50 MB chunks under
[models/vietasr/](../../models/vietasr/); `Pipeline.create()` fetches
`chunks.json` + `model.onnx.part*` + `vocab.txt` at load time, reassembles them
and verifies the SHA-256. The base URL comes from `dist/model-config.js`
(generated by `build-wasm.sh`, pinned to a release on jsDelivr) and can be
overridden with the `modelUrl` option to serve the model from your own origin.

The WASM module is compiled from the **exact same C++** as the desktop/mobile
bindings (`FeaturePipeline`, `CtcBeamSearch`, `PostProcessor`, `Units`,
`AudioResampler`) — so decoding behaviour is bit-identical. Only the encoder
inference is delegated to `onnxruntime-web`, because ONNX Runtime already ships
a mature WASM build.

## Install

```bash
npm install @viet-asr/web
```

## Usage

```js
import { Pipeline } from "@viet-asr/web";

const pipe = await Pipeline.create();

// decode an audio file to Float32 PCM with the Web Audio API
const ctx = new AudioContext();
const audioBuffer = await ctx.decodeAudioData(await file.arrayBuffer());
const pcm = audioBuffer.getChannelData(0);

const text = await pipe.transcribe(pcm, audioBuffer.sampleRate);
console.log(text);
```

### Streaming (live microphone)

For real-time transcription, feed audio chunks as they arrive — the transcript
grows with each call:

```js
const pipe = await Pipeline.create();
pipe.startStream();
// ... for each chunk of captured PCM:
const partial = await pipe.pushStream(pcm, sampleRate);  // transcript so far
// ... when the user stops:
const final = await pipe.finishStream();
```

[examples/index.html](examples/index.html) is a complete demo with a **live
microphone** mode (text appears as you speak) and a WAV file picker, both driven
by a Web Worker so the encoder never blocks the UI.

## Build from source

Requires the [Emscripten SDK](https://emscripten.org/docs/getting_started/downloads.html).

```bash
# activate emscripten
source /path/to/emsdk/emsdk_env.sh

# compile the DSP core (fbank + CTC + ITN) to WASM
cd bindings/webjs
bash build-wasm.sh
# -> dist/vietasr-core.js + dist/vietasr-core.wasm + dist/model-config.js

# install the JS dependency (onnxruntime-web)
npm install
```

The demo loads the model from the repo's `models/vietasr/`, so serve the
**repository root** over HTTP (WASM, workers and `fetch` all need a real origin):

```bash
# from the repo root
npx serve .
# open http://localhost:3000/bindings/webjs/examples/
```

The microphone needs a secure context — `localhost` qualifies.

## API

| Method | Signature | Notes |
|---|---|---|
| `Pipeline.create` | `(options?) => Promise<Pipeline>` | loads `model.onnx` chunks + `vocab.txt`, inits WASM + ORT |
| `pipeline.transcribe` | `(pcm: Float32Array, sampleRate?) => Promise<string>` | full-clip transcription |
| `pipeline.startStream` | `() => void` | begin a streaming session (clears state) |
| `pipeline.pushStream` | `(pcm: Float32Array, sampleRate?) => Promise<string>` | feed a chunk; returns the partial transcript so far |
| `pipeline.finishStream` | `() => Promise<string>` | flush the tail; returns the final transcript |
| `pipeline.reset` | `() => void` | clears streaming state |

`Pipeline.create` options:
- `modelUrl` — base URL of the model assets (`chunks.json`, `vocab.txt`,
  `model.onnx.part*`).
- `unitsText` + `encoderModel` — supply your own vocab string and ONNX model
  (`ArrayBuffer`/`Uint8Array`) to skip the fetch.
- `ortModuleUrl` — explicit URL to the `onnxruntime-web` ESM module. Required
  inside a Web Worker (no import map); omit it for bundler/npm use.
- `ortWasmPaths` — directory holding `onnxruntime-web`'s own `.wasm` files.

## What runs where

| Stage | Runtime |
|---|---|
| Resample → 16 kHz | WASM (`AudioResampler`) |
| 80-bin log-Mel fbank | WASM (`FeaturePipeline`) |
| Streaming Conformer encoder | onnxruntime-web (`model.onnx`) |
| CTC prefix beam search | WASM (`CtcBeamSearch`) |
| BPE detokenize | WASM (`PostProcessor` + `Units`) |
| Inverse text normalization | WASM (`ApplyItnVietnamese`) |

## Notes

- The WASM module exports a small C ABI (`vietasr_wasm_*`) defined in
  [src/wasm_api.cc](src/wasm_api.cc).
- **Inverse text normalization** runs inside the WASM core: spoken numbers are
  folded to digits — `"bốn mươi"` → `"40"`, `"... phần trăm"` → `"...%"`,
  `"ba phẩy năm"` → `"3.5"`. It applies to both streaming partials and the final
  transcript and is idempotent. A numeral still being spoken shows an
  intermediate value and self-corrects once it completes.
- **Streaming** (`startStream` / `pushStream` / `finishStream`) reuses the same
  chunked encoder path as `transcribe()`: `pushStream` runs every full encoder
  window currently available and buffers the tail until `finishStream`.
- `att_cache` / `cnn_cache` (the streaming Conformer state) are carried between
  chunks as `Float32Array`s on the JS side and fed back into each `session.run`.
- For lowest latency, serve the `.wasm` with `Content-Type: application/wasm`
  and enable cross-origin isolation so `onnxruntime-web` can use threads + SIMD.
